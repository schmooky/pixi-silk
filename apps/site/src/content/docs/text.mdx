`SilkText` from `pixi-silk/text` draws a string from distance-field glyphs, so a label under a
zooming camera keeps its edges where PixiJS `Text` turns into a stretched bitmap.

## Draw a label

<Demo name="sdf-text" height={320} caption="Turn off animate and drag the zoom slider. Both sides zoom around the same point." />

```ts
import { SilkText } from 'pixi-silk/text';

const label = new SilkText({
    text: 'Frame 1',
    fontFamily: 'Inter, system-ui, sans-serif',
    fontSize: 13,
    fontWeight: 600,
    fill: 0xffffff,
    anchor: 0.5,
});

app.stage.addChild(label);
label.text = 'Frame 2'; // laid out again before the next frame
```

PixiJS `Text` draws the string once into a canvas and shows that as a texture. SilkText stores
each glyph as a signed distance field instead, and the shader turns the distance into coverage per
screen pixel. [How it works](/docs/how-it-works/) covers the idea. All texts share one atlas texture.

Change one field with its setter (`label.fontSize = 18`) or several with `label.set({ ... })`.
Width, height, bounds and hit tests use the text box, as with PixiJS `Text`.

## Add an outline, a glow or a gradient

<Demo name="sdf-text-styles" height={380} caption="Change the outline, glow and weight. Watch the readout digits as the number changes." />

An outline or a glow reads the same distance field at a different distance, so it needs no filter.

```ts
import { horizontal } from 'pixi-silk';
import { SilkText } from 'pixi-silk/text';

const title = new SilkText({
    text: 'BIG WIN',
    fontSize: 48,
    fontWeight: 900,
    fill: horizontal(['#ffd60a', '#ff9f0a']),
    outline: { width: 3, color: 0x3a1c00 },
    shadow: { color: 0x000000, alpha: 0.6, blur: 6, offsetY: 4 },
});
const readout = new SilkText({ text: '72.4', fontSize: 32, tabularNumbers: true });
```

| Option | Default | What it does |
| --- | --- | --- |
| `fontFamily`, `fontSize`, `fontWeight`, `fontStyle` | system UI font, 16, 400, normal | Any CSS font. Glyphs are baked once at a fixed size |
| `fill` | white | A colour, or a linear, radial or conic gradient over the text box |
| `letterSpacing`, `lineHeight` | 0, font | Spacing in local units. Line height 0 uses the font's own |
| `align`, `wordWrap`, `wordWrapWidth`, `breakWords` | left, off, 100, off | Line layout, as in PixiJS `Text` |
| `anchor` | 0 | Point of the text box at the position |
| `outline` | none | `{ width, color, alpha }`, outside the glyph edge |
| `shadow` | none | `{ color, alpha, blur, offsetX, offsetY }`. Without an offset it is a glow |
| `dilate` | 0 | Grows or thins the glyphs, in local units |
| `tabularNumbers` | off | Digits share one width, so a changing number does not jitter |
| `kerning` | on | Pair kerning measured from Canvas |

Outlines and glows reach about a quarter of the font size. Past that the distance field runs out
and the effect is clamped. For a wider halo, put a blurred SilkGraphics shape behind the text.

## Small sizes

At 11 to 13 px a texel of the atlas is smaller than a screen pixel. SilkText then averages four
samples per pixel, so thin stems do not flicker. The bottom left of the first demo shows both
kinds of text at 11, 12 and 13 px.

Glyph shapes and widths match PixiJS `Text`, because both come from the same Canvas font and
`measureText`. Some platforms hint Canvas text to the pixel grid, so at 1x and no zoom its stems
can look a little crisper. From 2x, or under a camera, SilkText wins.

## Use SilkText inside widgets

Widgets that show a value take a `label` option, a function that builds their text. Pass
`silkLabel()` for widgets that sit under a zooming camera. The widget never imports SilkText
itself, so apps that do not use it do not ship it.

```ts
import { silkLabel } from 'pixi-silk/text';
import { ValuePill } from 'pixi-silk/ui/pill';

const pill = new ValuePill({ label: silkLabel({ tabularNumbers: true }) });

pill.show('42 px');
```

For a label that holds icons, `silkRichLabel()` makes a `SilkRichText` instead. Name the objects
once, then write their tokens in any text the widget shows. The icon counts in the label's width,
so the pill grows to fit it.

```ts
import { SilkGraphics } from 'pixi-silk';
import { silkRichLabel } from 'pixi-silk/text';
import { ValuePill } from 'pixi-silk/ui/pill';

const up = () => new SilkGraphics().poly([0, 8, 5, 0, 10, 8]).fill(0x30d158);
const trend = new ValuePill({ label: silkRichLabel({ up: { object: up, height: 'cap' } }) });

trend.show('{up} 12%');
```

To let people click and type into a text, wrap it in a `TextEditor`. See [Editing text](/docs/editing-text/).

## Right-to-left text

<Demo name="text-rtl" height={360} caption="Numbers, percentages and Latin words keep their order inside the Arabic and Hebrew lines. Right: the same glyphs at 4x." />

Arabic and Hebrew work without options. A paragraph whose first letter is right to left reads right
to left, and `align: 'start'` (the default) puts it on the right. Numbers, prices and Latin words
inside it keep reading left to right, the way an HTML element with `dir="auto"` shows them.
Brackets are mirrored. PixiJS `Text` draws with the canvas direction, left to right by default, so
it can order a right-to-left line that holds Latin words differently.

```ts
import { SilkText } from 'pixi-silk/text';

const price = new SilkText({ text: 'السعر 1,234.56 دولار', fontSize: 18 });
const forced = new SilkText({ text: 'v2.1', direction: 'rtl' }); // 'ltr', 'rtl' or 'auto' (default)
```

Joined Arabic letters are measured and baked as one glyph per run, so Canvas shapes them with the
font: initial, medial and final forms, and ligatures such as lam alef. Harakat ride on their letter.
Each new word costs one atlas entry, so long Arabic texts fill the atlas faster than Latin ones.

The line order follows the Unicode bidi algorithm. After Arabic letters, digits count as Arabic
numbers, so a sign before them shows on their right: `-5` reads `5-`, as in the browser. Put a
left-to-right mark (`\u200E`) before the sign to keep it on the left.

When you put a value of unknown direction into a sentence, such as a name or a file name, wrap it
in U+2068 and U+2069 (first strong isolate). It then takes its own direction and leaves the
punctuation around it alone. The embedding and override controls (U+202A to U+202E) work too, and
paired brackets take the direction of what they enclose.

```ts
import { SilkText } from 'pixi-silk/text';

const name = 'Dana';
const line = new SilkText({ text: `\u0645\u0631\u062d\u0628\u0627 \u2068${name}!\u2069` });
```

## Every script, and objects inside the text

<Demo name="text-scripts" height={660} caption="One line per script, then paragraphs with no spaces to break at, then text with SilkGraphics icons inside it. Tick boxes to see the line boxes." />

Text in any script draws without options. Scripts that need shaping are baked a word or a run at a
time, so Canvas shapes them with the font. That covers Burmese, Thai, Khmer, Lao, the Indic
scripts, Arabic, emoji sequences and letters with combining accents. Latin, Cyrillic, Greek, Chinese, Japanese and
Korean are baked one character at a time.

Nothing is cut. Each glyph is drawn with room to spare, and the atlas keeps the ink it finds in
the pixels, not the box `measureText` reports, which is too small for stacked marks. With
`lineHeight` at 0, lines grow to fit the tallest ink and the outline, so Burmese or Vietnamese
stacks never touch the next line. A fixed `lineHeight` is kept as given. Bounds cover the ink, so
filters and culling do not clip it either.

Lines wrap without spaces where the script allows it. Chinese and Japanese break between characters
but never before closing punctuation or small kana. Korean breaks between syllables, or only at
spaces with `wordBreak: 'keep-all'`. Thai, Burmese, Khmer and Lao break between words, found with
`Intl.Segmenter`.

Outlines are drawn for every glyph before any fill, so a thick outline never covers the letter
next to it, even with tight letter spacing.

To put an icon or any sprite in a line, write `{name}` in the text and use `SilkRichText`:

```ts
import { Sprite, Texture } from 'pixi.js';
import { SilkGraphics } from 'pixi-silk';
import { SilkRichText } from 'pixi-silk/text';

const status = new SilkRichText({
    text: 'Synced {dot} 2 min ago, rated {star} 4.8',
    fontSize: 24,
    inlines: {
        // scaled to the height of capitals and digits, centred on them
        dot: { object: new Sprite(Texture.WHITE), height: 'cap', margin: 2 },
        // a function makes one object per {star} in the text
        star: { object: () => new SilkGraphics().star(0, 0, 5, 10, 4).fill(0xffd60a), height: 'em', align: 'center' },
    },
});
```

Each token takes a box that wraps, aligns and follows right-to-left order like a character. A box
taller than the text grows its line. `align` places it. `middle` (the default) centres it on
capital letters and digits, and `center` on the line box. `baseline` stands it on the baseline, and
`top` and `bottom` align it with the font's ascent and descent. `offsetY` nudges it. Sizes are local
units or `em`, `cap` and `line`. Plain `SilkText` takes the same boxes as
`inlines: { icon: { width, height } }` and returns where they landed from `inlineRects()`.

`anchor` on a `SilkRichText` is the anchor of its text, and the objects move with it. They also
follow the text object's own position and scale, wrapping and right-to-left order. A box sticks to
the letters and digits next to it, so `{icon}100` never splits across lines. Lines break between
two boxes and between a box and Chinese, Japanese or Korean text, and at spaces as usual.

`tabularNumbers` works for every digit set: ASCII, Arabic-Indic, Persian, Devanagari, Thai, Burmese
and the others each get the width of their widest digit.

## Long text in a small box

<Demo name="text-fit" height={420} caption="Drag the width. Left: cut after two lines. Middle: the font shrinks to fit, then cuts. Right: justified, with kashida in the Arabic paragraph." />

Translations run longer than the text a layout was drawn for. Three options keep text in its box:

- `maxLines` drops the lines after it, and the last line ends in `ellipsis` (default U+2026, the ellipsis
  character, or `null` for none).
- `maxWidth` cuts a line that does not wrap when it gets wider. `maxHeight` limits how many lines
  fit by height.
- `shrinkToFit` first makes the font smaller, down to `minFontSize` (half the size by default),
  until the text fits. What still does not fit is cut. `renderedFontSize` says the size it used,
  and `truncated` whether anything was cut.

```ts
import { SilkText } from 'pixi-silk/text';

const title = new SilkText({ text: 'Settings', fontSize: 24, maxWidth: 160, shrinkToFit: true, minFontSize: 14 });
const note = new SilkText({ text: 'A long description', wordWrap: true, wordWrapWidth: 200, maxLines: 2 });
```

`align: 'justify'` stretches every wrapped line to the full width and keeps the last line of each
paragraph at its start. Arabic lines stretch their words with kashida (tatweel) before the spaces
grow, and never inside lam alef. `kashida: false` turns that off. Lines with no spaces, such as
Chinese and Japanese, spread the room between characters.

Tabs line up on stops every `tabSize` spaces (8 by default) from the start of the line.
`letterSpacing` is not applied inside Arabic words, which would break their joins, nor inside words
of Burmese, Khmer and the Indic scripts, which are baked whole.

## Fonts and the atlas

Each glyph is drawn with Canvas2D at 48 px the first time it appears, then turned into a distance
field. The atlas is one 8-bit texture, 1024 texels wide, that doubles in height up to 4096. When it
is full it starts over, and every text bakes what it needs again.

Load web fonts before the first text uses them, for example with `document.fonts.load('600 16px Inter')`.
Glyphs baked while a font was still loading are baked again once it is ready.

For a different trade-off, make your own atlas and pass it to the texts that should use it:

```ts
import { SdfAtlas, SilkText } from 'pixi-silk/text';

const big = new SdfAtlas({ size: 64, radius: 24 }); // sharper corners far in, longer glows
const heading = new SilkText({ text: 'Overview', fontSize: 40, atlas: big });
```

## Where it stops

Corners round off slightly at extreme zoom, because a single-channel distance field cannot hold a
sharp corner. At the default 48 px bake the rounding is about a fiftieth of the font size.

Emoji keep their colours. They come from a second, colour texture, so deep zoom softens them like
any bitmap, while their outline and shadow stay sharp. Latin text gets no font ligatures, because
its letters are baked one by one.

Long texts in Burmese, Khmer or the Indic scripts bake a glyph per word, so they fill the atlas
faster than Latin text. `atlas.usage` says how full it is, from 0 to 1. When it is full, it starts
over with the glyphs in use. For apps with a lot of such text, give their texts an atlas of their
own.

SilkText runs on WebGL2 and WebGPU. Pixi's WebGL1 fallback is not supported.
