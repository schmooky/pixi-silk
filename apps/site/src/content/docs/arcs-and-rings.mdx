## Progress rings

The demo draws each track with `circle()` and its progress with `arcSweep()`, using
`conic()` for a gradient that spans the arc.

To keep the colours fixed around a full turn while progress grows, draw two half-arcs. Each
samples its half of the same ramp, and `sweepDirection: 'shape'` keeps the gradient pointing
with the arc. This uses only the public API:

```ts
import { conic, SilkGraphics } from 'pixi-silk';

const stops = [0xe8134f, 0xff5aa0];
const first = conic(stops, { range: [0, 0.5], sweep: Math.PI, sweepDirection: 'shape' });
const second = conic(stops, { range: [0.5, 1], sweep: Math.PI, sweepDirection: 'shape' });

function drawProgressRing(g: SilkGraphics, progress: number) {
    const cx = 100, cy = 100, radius = 60, width = 14;
    const sweep = Math.max(0, Math.min(progress, 1)) * Math.PI * 2;

    g.circle(cx, cy, radius).stroke({ width, color: 0x3a0717 });
    if (sweep > 0) {
        g.arcSweep(cx, cy, radius, -Math.PI / 2, Math.min(sweep, Math.PI))
            .stroke({ width, cap: 'round', gradient: first });
    }
    if (sweep > Math.PI) {
        g.arcSweep(cx, cy, radius, Math.PI / 2, sweep - Math.PI)
            .stroke({ width, cap: 'round', gradient: second });
    }
}
```

At zero progress, you can draw a dot at 12 o'clock. To show progress above 100%, add another
arc in the final colour for the extra lap.

## Arcs

```ts nocheck
g.arc(cx, cy, radius, startAngle, endAngle, anticlockwise?);   // canvas semantics
g.arcSweep(cx, cy, radius, startAngle, sweep);                 // signed sweep, clockwise on screen
```

Arcs are open curves, so you stroke them. `cap` sets the shape of the ends. The default is
`'butt'`, as in Pixi.
Angles are in radians with y pointing down, so `-Math.PI / 2` is 12 o'clock and positive sweeps
turn clockwise. Each arc starts its own subpath. Unlike `Graphics.arc`, it does not connect to the
previous point.

```ts
g.arcSweep(100, 100, 60, -Math.PI / 2, Math.PI * 2 * progress)
    .stroke({ width: 14, cap: 'round', color: 0x30d158 });
```

A sweep of `2π` or more covers a full ring. `arcSweep()` preserves the extra turns, so the
end keeps moving over the previous lap. For round-capped strokes, the shadow appears when the
end cap starts touching the start cap near a full turn. It shades the earlier stroke beneath
the tip and fades out within one stroke width of the tip centre. Dashed arcs do not use it.

Set `tipShadow: true` to enable the shadow explicitly. It is already on by default. Set
`tipShadow: false` to disable it, even when the caps overlap or the sweep passes a full turn.

`arc()` retains canvas semantics and stops at one turn. Each ring still uses one primitive.


## Gradients on arcs

A `conic()` gradient on an arc spans that arc. Its start and sweep default to the arc's own. So the
ramp runs from the start cap to the end cap. Short round arcs ease out of the first color
until their length reaches one cap diameter (the stroke width). On overlapping turns, the latest lap is visible.

```ts
const RING = conic([0xfa114f, 0xff5e8a]);

g.arcSweep(100, 100, 60, -Math.PI / 2, sweep).stroke({
    width: 16, cap: 'round', gradient: RING, tipShadow: true,
});
```

## Sectors and donut segments

```ts
g.sector(cx, cy, radius, startAngle, endAngle, innerRadius = 0, cornerRadius = 0);
```

`innerRadius` turns a pie slice into a donut segment. `cornerRadius` rounds all of its corners.
Sectors are closed shapes, so you can fill them, stroke them, or both. Gauges, pie charts and radial
menus are a loop of sectors.

```ts
const slices = [0.4, 0.25, 0.2, 0.15];
const COLORS = [0x0a84ff, 0x30d158, 0xffd60a, 0xff375f];
let a = -Math.PI / 2;

for (const [i, share] of slices.entries()) {
    const sweep = share * Math.PI * 2;

    g.sector(120, 120, 90, a + 0.02, a + sweep - 0.02, 50, 6).fill(COLORS[i]);
    a += sweep;
}
```
