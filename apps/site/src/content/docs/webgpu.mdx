pixi-silk has two versions of its shader. WebGL2 runs the GLSL one and WebGPU runs a WGSL port of it.
Both compute the same distances, coverage and paints, so a scene looks the same on either.

## Pick a renderer

`createSilkApp` creates a WebGL2 app by default. Pass `preference: 'webgpu'` to use WebGPU where the
browser has it:

```ts
import { createSilkApp, SilkGraphics } from 'pixi-silk';

const silk = await createSilkApp({ parent: document.body, preference: 'webgpu' });

silk.app.renderer.name; // 'webgpu', or 'webgl' where the browser has no WebGPU
silk.app.stage.addChild(new SilkGraphics().circle(60, 60, 40).fill(0x30d158));
```

Pixi tries WebGPU first and falls back to WebGL2 on its own. When it gets WebGPU, `createSilkApp`
loads the WGSL shader before it resolves. You need nothing else.

WebGL2 stays the default. Every current browser has it, it starts faster, and it is the renderer
the library is tested on most. Choose WebGPU when the rest of your app needs it.

## Your own Pixi application

The WGSL shader lives in its own module, `pixi-silk/webgpu`, so WebGL2 apps never download it. If
you create the application yourself, call `enableWebGPU()` once before you create any SilkGraphics:

```ts
import { Application } from 'pixi.js';
import { SilkGraphics } from 'pixi-silk';
import { enableWebGPU } from 'pixi-silk/webgpu';

const app = new Application();

await app.init({ preference: 'webgpu' });
enableWebGPU();
app.stage.addChild(new SilkGraphics().circle(60, 60, 40).fill(0x30d158));
```

Objects created before the call only have the WebGL2 program. On WebGPU, Pixi skips them and logs
"Mesh shader has no gpuProgram". Calling `enableWebGPU()` on a WebGL2 app is harmless.

## Glass

`Glass` works on both renderers. WebGL2 reads the backdrop from the back buffer, which `Glass` turns
on the first time it draws. WebGPU copies the backdrop from the render target, so it needs no back
buffer.

## Differences

The two shaders are line-for-line ports. A few details differ because of the APIs:

- The dither noise is seeded by the pixel position. WebGPU counts rows from the top and WebGL2 from
  the bottom, so the grain pattern is mirrored. Its strength is the same.
- WebGPU reads gradient ramps with two exact texel loads and blends them in the shader. WebGL2
  uses the GPU's linear filter, which can round the blend weight to 8 bits.
- Derivative precision (`dpdx` and `dFdx`) is up to the GPU on both, so edges can differ by a
  rounding step.

Check a page on WebGPU by adding `?renderer=webgpu` to its URL. Every demo on it then runs on
WebGPU.
