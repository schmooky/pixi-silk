The root import `pixi-silk` holds the drawing core. Everything else has its own entry point, so
an app that only draws shapes never downloads the text renderer or the editor widgets.

```ts
import { SilkGraphics } from 'pixi-silk';
import { SilkText } from 'pixi-silk/text';
import { SilkButton } from 'pixi-silk/ui/button';
```

The UI widgets, text, layout, glass, glow and the WebGPU shader are not in the root import. An
import of `SilkText` from `pixi-silk` fails to compile.

## Core

| Import | What it holds | Import it when |
|---|---|---|
| `pixi-silk` | `SilkGraphics`, gradients (`linear`, `radial`, `conic`, `along`, `mesh`), `createSilkApp`, `enableSilkBatching`, `Spring`, `damp`, `ease`, colour and curve helpers | always |
| `pixi-silk/webgpu` | `enableWebGPU()`, the WGSL shader | you create your own Pixi app with WebGPU. See [Renderers](/docs/renderers/) |
| `pixi-silk/signal` | `signal`, `computed`, `watch`, `batch` | you read or write widget state, which is kept in signals |

## Text, layout and effects

| Import | What it holds | Import it when |
|---|---|---|
| `pixi-silk/text` | `SilkText`, `silkLabel`, `SdfAtlas`, text layout and caret helpers | you draw labels. See [Text](/docs/text/) |
| `pixi-silk/layout` | `LayoutNode`, a flex layout engine with no Pixi in it | you lay out boxes in a worker, a test or a server. See [Layout engine](/docs/layout-engine/) |
| `pixi-silk/ui/layout` | `SmartContainer`, `FlexContainer`, `simulateViewport`, `layoutDebug` | you place Pixi containers on a responsive screen. See [Layout](/docs/layout/) |
| `pixi-silk/glass` | `Glass`, `GlassFilter` | you want frosted panels. See [Glass & glow](/docs/glass-and-glow/) |
| `pixi-silk/glow` | `Glow`, `Aurora`, `neon`, `halo`, `shadowStack`, light rays | you want neon, halos or light beams |

## Everything at once

`pixi-silk/ui` re-exports every widget above, plus `pixi-silk/selection`, `pixi-silk/history` and
`pixi-silk/path`. It is handy in a prototype. In an app, import from the widget's own path so the
bundle holds only the widgets you use.

The package has no side effects, so a bundler drops the widgets you do not use from either
import. The narrow paths make that independent of how well your bundler tree-shakes.
